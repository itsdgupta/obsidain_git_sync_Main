# 4-Week Figma Hackathon Prep — Brief Plan (pa, da, di, ya)

## Week 1 — Skills + Tests
| Days | Cluster | Assignment | Test |
|---|---|---|---|
| 1–2 | Core Interface (frames, auto layout, variants,components) | Build same UI (login/card) using auto layout + variant components | Swap files — can others read your layer structure? |
| 3–4 | Prototyping (Smart Animate, overlays, logic) | Add 3-screen interactive flow to Cluster 1 UI | 60-sec live demo each |
| 5–6 | Visual Craft (type, color, icons, effects) | Restyle a screen with type scale + WCAG-checked colors | Peer review, 1–5 rubric |
| 7 | Checkpoint | — | Review results, plan pairing for Week 2 |

## Week 2 — Remaining Skills + Pacing
| Days | Cluster | Assignment | Test |
|---|---|---|---|
| 8–9 | Design Systems (tokens, naming) | Pairs build 6-component mini design system | Other pair builds a screen using only it |
| 10–11 | UX/FigJam (flows, IA, wireframes) | Wireframe a throwaway hackathon prompt | Group critique — flow logical w/o explanation? |
| 12 | Dev Handoff & Plugins (light touch) | Inspect Dev Mode, pick 2 useful plugins | No formal test |
| 13–14 | Buffer | Remediation for whoever's lagging | — |

## Week 3 — Live Collaborative Project
- Pick a real, scoped-down project (ideally close to actual hackathon theme)
- Assign roles by Week 1–2 checkpoint strengths, not arbitrarily
- Day 1: plan/wireframe → Days 2–4: build → Day 5: review → Days 6–7: iterate
- Stress-test multiplayer editing (branching, comments)

## Week 4 — Mock Hackathon
- Simulate the exact real hackathon time window
- Include: time-boxed problem selection, hard design-freeze deadline, 3–5 min pitch
- Real post-mortem after — biggest source of improvement

**📅 Week 1 — Skills + Tests**

**Day 1** 🎯 Cluster: Core Interface (frames, auto layout, variants, components) 📌 Task: Start building a login screen (or card component) using auto layout + variant components. Focus on clean frame structure and naming layers properly.

**Day 2** 🎯 Cluster: Core Interface (continued) 📌 Task: Finish the login/card UI. Make sure components have variants (e.g., default/hover/error states) and layers are named clearly. ✅ Test: Swap files with a partner — can they read your layer structure without explanation?

**Day 3** 🎯 Cluster: Prototyping (Smart Animate, overlays, logic) 📌 Task: Begin adding a 3-screen interactive flow on top of your Cluster 1 UI. Set up screen 1 → screen 2 transition using Smart Animate or overlays.

**Day 4** 🎯 Cluster: Prototyping (continued) 📌 Task: Complete the 3-screen flow (screen 2 → screen 3) with proper interaction logic (tap, hover, overlay triggers). ✅ Test: 60-second live demo — present your flow to the group.

**Day 5** 🎯 Cluster: Visual Craft (type, color, icons, effects) 📌 Task: Restyle one screen from your project — apply a proper type scale (headings/body/labels) and start checking color contrast for WCAG compliance.

**Day 6** 🎯 Cluster: Visual Craft (continued) 📌 Task: Finalize restyled screen — icons, effects (shadows/blur), and confirm all text meets WCAG AA contrast ratio (4.5:1 minimum for body text). ✅ Test: Peer review using a 1–5 rubric (clarity, hierarchy, accessibility, consistency, polish).

**Day 7** 🎯 Checkpoint 📌 Task: No new build. Review Week 1 results as a group, share feedback, and set up pairing/groups for Week 2.
